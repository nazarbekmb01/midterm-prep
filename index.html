Number systems

Denary (base 10), binary (base 2), hexadecimal (base 16) and octal (base 8). How to convert between them, and why programmers like hex.

Why binary?

A computer is made of millions of tiny switches. Each switch is either off (0) or on (1). That is why all data — numbers, text, pictures, sound — must be turned into binary before a computer can process it. One binary digit is a bit.

Place values

In every number system, each column is worth the base multiplied by the column on its right.

Denary (base 10)10³ = 100010² = 10010¹ = 1010⁰ = 1
Binary (base 2)2³ = 82² = 42¹ = 22⁰ = 1
Octal (base 8)8³ = 5128² = 648¹ = 88⁰ = 1
Hexadecimal (base 16)16³ = 409616² = 25616¹ = 1616⁰ = 1

For one byte (8 bits) the binary place values are 128 64 32 16 8 4 2 1. Learn this row by heart.

Easy way

Three rules for every number system

This is the method from our lesson on 2 September. You only need three rules, and they work the same way for base 2, 8 and 16. If the other methods below feel hard, start here.

Rule 1Denary → any base

Divide by the base in a ladder until the answer is smaller than the base. Read the last answer, then the remainders going up.

Rule 2Any base → denary

Number the digits from the right, starting at 0. Multiply each digit by basenumber and add everything.

Rule 3Octal / hex ↔ binary

Use the table. Each octal digit = 3 bits. Each hex digit = 4 bits.

Rule 1 · The division ladder

Write the number and the base next to it. Write the answer under the base, then divide that answer again. Each step moves one place to the right, like stairs. Stop when the answer is smaller than the base.

23 → binary
137 → octal
558 → hexadecimal

The remainder 14 is written as E in hex.

How to read the answer: start with the circled number at the bottom of the stairs (the last answer), then read the circled remainders going up and to the left.

Rule 2 · Number the positions

Write a small number above each digit: 0 for the right-most digit, then 1, 2, 3… to the left. This number is the power of the base.

10110₂ → denary
721₈ → denary
3FA₁₆ → denary

Remember: A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

This table shows the numbers 0–15 in all four systems. For octal use only the last 3 bits (rows 0–7). For hex use all 4 bits.

Hexadecimal

Hex is base 16, so it needs 16 digits: 0–9 and then A=10, B=11, C=12, D=13, E=14, F=15. Because 16 = 2⁴, one hex digit is exactly 4 bits (a nibble).

Binary → hex

Split the bits into groups of 4 from the right. Add zeros on the left of the last group if needed. Change each group into one hex digit.

Example · 101111100001 1011 | 1110 | 0001 → B | E | 1 → BE1
Example · 10000111111101 0010 | 0001 | 1111 | 1101 → 21FD

Hex → binary

Change each hex digit into 4 bits.

Example · F935 F = 1111, 9 = 1001, 3 = 0011, 5 = 0101 → 1111 1001 0011 0101

Hex → denary

Multiply each digit by its place value (256, 16, 1) and add.

Example · 45A (4×256) + (5×16) + (10×1) = 1024 + 80 + 10 = 1114

Denary → hex

Divide by 16 again and again. Change remainders 10–15 into A–F. Read from bottom to top.

Example · 2004 2004 ÷ 16 = 125 r 4 · 125 ÷ 16 = 7 r 13 (D) · 7 ÷ 16 = 0 r 7 → 7D4
Shortcut for numbers up to 255: divide by 16 once. The whole part is the first digit, the remainder is the second. 200 ÷ 16 = 12 r 8 → C8.

Octal (base 8)

Octal uses digits 0–7. Because 8 = 2³, one octal digit is exactly 3 bits. Group bits in threes from the right.

Example · 714₈ → binary 7 = 111, 1 = 001, 4 = 100 → 111001100
Example · 117₈ → denary (1×64) + (1×8) + (7×1) = 79

Why do we use hexadecimal?

Shorter

One hex digit replaces four bits. 11010111 becomes D7.

Easier to read

People can read, remember and copy hex much more easily than long rows of 0s and 1s.

Fewer mistakes

Fewer characters mean fewer copying errors. And it is still very easy to change back into binary.

Where hex is used

  • MAC addresses — a unique number for a network card, e.g. 00-1C-B3-4F-25-FE. The first 3 pairs identify the manufacturer, the last 3 pairs identify the device.
  • HTML colour codes — #RRGGBB, two hex digits each for red, green and blue.
  • Error codes and memory addresses — shown in hex so that programmers can find the problem location.
  • IPv6 addresses — 128-bit addresses written in hex, e.g. a8fb:7a88:fff0:0fff:3d21:2085:66fb:f0fa.

Text

Every character you type — letters, digits, spaces, punctuation — is stored as a binary code. A list of characters and their codes is called a character set.

Character sets

Character setBits per characterNumber of charactersWhat it covers
ASCII72⁷ = 128English letters (26 upper case, 26 lower case), digits, punctuation, space
Extended ASCII82⁸ = 256ASCII + 128 more codes for some non-English letters and graphic symbols
Unicode16over 65 000Characters from almost all languages: Kazakh, Russian, Chinese, Arabic… and emoji
Why Unicode? ASCII has too few codes for other alphabets. Unicode uses more bits, so it can store many more different characters.
Useful codes A = 65 = 01000001 · a = 97 = 01100001 · 0 = 48 = 00110000 · space = 32 = 00100000
Codes are in order, so B = 66, C = 67 … and a lower-case letter is always 32 more than its upper-case letter.

Images

A bitmap image is a grid of tiny dots called pixels. Each pixel is stored as a binary number that says its colour.

Key words

Pixel

The smallest single dot of colour in an image.

Image resolution

The number of pixels that make up an image (width × height). Higher resolution → more detail, but a bigger file.

Colour depth

The number of bits used to represent the colour of each pixel. More bits → more colours, but a bigger file.

Number of colours

colours = 2colour depth

Colour depth1 bit2 bits3 bits4 bits8 bits24 bits
Colours2481625616 777 216

Most modern computers use 24-bit colour: 8 bits each for red, green and blue — over 16 million colours.

Try it

Resolution and colour depth

Change the resolution and colour depth of the same picture. Watch the quality and the file size.

    Calculating the file size of an image

    file size (bits) = width × height × colour depth

    Then: ÷ 8 → bytes, ÷ 1024 → KiB, ÷ 1024 → MiB.

    Example · 2 × 2 pixels, colour depth 2 (2 × 2) × 2 = 8 bits = 1 byte
    Example · 640 × 480 pixels, colour depth 8 bits → KiB
    1. 640 × 480 = 307 200 pixels
    2. 307 200 × 8 = 2 457 600 bits
    3. 2 457 600 ÷ 8 = 307 200 bytes
    4. 307 200 ÷ 1024 = 300 KiB
    Smart shortcut: if the colour depth is 8 bits, each pixel is exactly 1 byte, so bytes = number of pixels. If it is 16 bits, bytes = pixels × 2. If 24 bits, bytes = pixels × 3.

    Data representation 8.DR.06 · 8.DR.07

    Sound

    Real sound is an analogue wave. A computer measures the wave many times every second and stores each measurement as a binary number.

    From analogue to digital

    1. A microphone captures the sound as an analogue signal.
    2. Software measures the amplitude (height) of the wave at regular time intervals. Each measurement is a sample.
    3. Each sample is stored as a binary number.

    Sample rate

    The number of samples taken per second. Measured in hertz (Hz). 44 100 Hz = 44 100 samples every second.

    Sample resolution

    The number of bits used to store each sample (also called bit depth). 4 bits → 2⁴ = 16 possible amplitude levels.

    Try it

    Sound sampler

    The grey line is the real sound. The amber dots are the samples. The amber steps are what the computer stores. Press play to hear the difference.

    Higher sample rate or higher resolution

    AdvantagesDisadvantages
    Better sound quality, closer to the real soundBigger file size, needs more storage
    Less distortionTakes longer to download / upload

    Calculating the file size of a sound

    file size (bits) = sample rate × sample resolution × length (seconds) × channels

    Mono = 1 channel. Stereo = 2 channels (left and right), so the file is twice as big. Remember to change minutes into seconds.

    Example · mono, 44 100 Hz, 8 bits, 20 seconds → KiB
    1. 44 100 × 8 × 20 = 7 056 000 bits
    2. 7 056 000 ÷ 8 = 882 000 bytes
    3. 882 000 ÷ 1024 ≈ 861.33 KiB
    Example · stereo CD, 44 100 Hz, 16 bits, 60 minutes → MiB
    1. 60 minutes = 3600 seconds
    2. 44 100 × 16 × 3600 × 2 = 5 080 320 000 bits
    3. ÷ 8 = 635 040 000 bytes
    4. ÷ 1024 ÷ 1024 ≈ 605.62 MiB

    Data storage

    Units of memory size, how to convert between them, and why files are compressed.

    Units

    UnitEqual to
    1 bita single 0 or 1
    1 nibble4 bits
    1 byte8 bits
    1 kibibyte (KiB)1024 bytes
    1 mebibyte (MiB)1024 KiB
    1 gibibyte (GiB)1024 MiB
    1 tebibyte (TiB)1024 GiB
    Rule: going to a bigger unit → divide (÷ 8 from bits to bytes, then ÷ 1024 each step). Going to a smaller unit → multiply.
    Example · 64 GiB → bytes
    1. 64 × 1024 = 65 536 MiB
    2. 65 536 × 1024 = 67 108 864 KiB
    3. 67 108 864 × 1024 = 68 719 476 736 bytes

    Bonus · Compression

    Big files take more storage and more time to send. Compression makes files smaller.

    Lossy

    Removes some data forever (details people hardly notice). Much smaller file. Used for photos (JPEG), music (MP3), video.

    Lossless

    No data is lost — the original file can be rebuilt exactly. Used for text, programs, PNG images. Example: RLE.

    Run-length encoding (RLE) replaces a run of the same value with how many + which value. AAAABBBCCD → 4A 3B 2C 1D.

    Boolean logic 8.BL.01 – 8.BL.05

    Boolean logic

    Logic gates take inputs of 0 (False) and 1 (True) and give one output. We combine them into circuits to make decisions — like a burglar alarm.

    Key words

    TermMeaningExample
    BooleanA type of data with only two values: True or False.is_active = True
    Truth valueThe actual value of a condition: True (1) or False (0).10 > 5 is True
    Truth tableA table that shows all possible inputs and the output for each one.2 inputs → 4 rows
    Logic gateA part of a circuit that uses one logic rule to give an output.AND needs all inputs = 1
    Logic circuitTwo or more logic gates joined together.An alarm circuit
    ConditionA test or question with a True/False answer.Is the door open?
    RuleThe action the system takes because of the result of a condition.If True, ring the alarm

    The three gates

    Rows of a truth table: 2 inputs → 2² = 4 rows, 3 inputs → 2³ = 8 rows. Always write the inputs in counting order: 000, 001, 010 … 111.

    Combining gates

    The output of one gate can be the input of another. Work from the inputs to the output. Give each middle wire a name (P, Q) and fill in its column first — these are intermediate outputs.

    Circuit → expression Start at the output gate and write its rule. Put brackets around each gate that feeds into it.
    AND gate whose inputs are (NOT A) and (B OR C) → X = (NOT A) AND (B OR C)
    Expression → circuit Start with the innermost brackets. Draw those gates first, then join their outputs into the next gate.
    X = A AND (NOT (B OR C)): draw B OR C → put it through NOT → AND with A.
    Try it

    Expression lab

    Type any expression with AND, OR, NOT and brackets. You get the circuit and the full truth table with intermediate columns. Click a row to see which wires are on.

    Logic in real life

    Read the problem and look for the words and, or, either … or, not. Give each condition a letter.

    Example · Car alarm The alarm sounds (Y = 1) when the system is on (S = 1) and either a door is opened (D = 1) or a window is broken (W = 1).
    “either … or” goes in brackets → Y = S AND (D OR W)
    Example · Greenhouse window A window opens (X = 1) when it is hot (T = 1) and it is not raining (R = 1 means raining).
    → X = T AND (NOT R)

    Cheat sheet

    Everything to remember on one page. Copy it into your notebook by hand — that is a good way to learn it.

    Place values

    Binary: 128 64 32 16 8 4 2 1
    Octal: 512 64 8 1
    Hex: 4096 256 16 1

    Binary → hex: groups of 4 from the right.
    Binary → octal: groups of 3 from the right.
    Denary → other base: divide, read remainders bottom to top.

    Hex digits

    Why hex? Where?

    Why: shorter, easier to read and remember, fewer mistakes, easy to convert to binary.
    Where: MAC addresses, HTML colours (#RRGGBB), error codes / memory addresses, IPv6.

    Text

    ASCII: 7 bits, 128 characters.
    Extended ASCII: 8 bits, 256.
    Unicode: 16 bits, 65 000+, all languages.
    A = 65, a = 97, space = 32

    Images

    bits = width × height × colour depth

    colours = 2depth. Higher resolution or depth → better quality, bigger file.

    Sound

    bits = rate × resolution × seconds × channels

    Mono = 1, stereo = 2. Sample rate = samples per second (Hz). Resolution = bits per sample.

    Units

    8 bits = 1 byte · 4 bits = 1 nibble
    1024 B = 1 KiB · 1024 KiB = 1 MiB
    1024 MiB = 1 GiB · 1024 GiB = 1 TiB

    Bigger unit → ÷. Smaller unit → ×.

    Logic gates

    AND = 1 only if all inputs are 1 (A.B)
    OR = 1 if at least one input is 1 (A+B)
    NOT = the opposite, one input (Ā)
    Rows = 2inputs

    Compression

    Lossy: data removed forever, much smaller (JPEG, MP3).
    Lossless: original rebuilt exactly (PNG, text). RLE: AAAABB → 4A 2B.
